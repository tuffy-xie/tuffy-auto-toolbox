# Tuffy 的自动百宝箱

一台放在家里的 Android 手机，每天自动帮你做完这些日本 App 的每日任务：

| App | 每天做什么 | 默认时间（JST） |
|---|---|---|
| **ANA Pocket** | 登录奖励与月度徽章视频 → 接取出行挑战与 Boost → 每日广告（官方上限 25 次） | 00:03 |
| **楽天 PointClub** | 1ポイントミッション、ガラガラポン、PICKUP、三项达成后的 bonus 抽奖 | 09:15（默认关闭） |
| **いきなり！ステーキ** | 每日飞镖 | 09:30（默认关闭） |
| **TikTok Lite** | 14 天连续签到、领取昨日奖励、解锁明日奖励 | 07:30（默认关闭） |

签到类 App 默认关闭，在首页对应卡片上打开开关才会每天执行；时间可改。

运行受阻且满足恢复条件时会有限续跑。正常收尾时，Tuffy 保留自己和用户锁定的最近任务卡片，清理其他未锁定卡片后锁屏。

> 版本 **22.0.14-R47（versionCode 44）**，包名 `com.anapocket.auto`。此分支提供源码与真机记录。11 月 13 日签名构建保存在本地，下载文件待发布。

## 1. 获取源码与安装包

此分支暂未附签名 APK。可以按第 8 节编译。在已有签名安装包的情况下，核对其 SHA256 和签名证书后，再按第 3 节安装。

## 2. 需要什么

- Android 7.0 以上（实测：小米 HyperOS / Android 14）。
- 手机系统时区或业务按 **日本时间（JST）** 计算。
- 手机上已安装并登录好要用的 App（ANA Pocket、楽天 PointClub、いきなり！ステーキ、TikTok Lite，用哪个装哪个）。
- 建议用一台**专门挂机**的手机，常插电、连 Wi‑Fi。
- 定时任务需要可操作的手机界面。遇到密码或其他安全锁屏时，需要用户本人解锁。

## 3. 安装（5 分钟）

1. 把 APK 传到手机，用「文件管理」打开 → 安装。如系统要求允许此来源，请先核对上面的 APK SHA256，再按手机提示完成安装。
2. 打开 **Tuffy的自动百宝箱**，进底部「设置」页，把下面每一行都点开，在系统页面里允许：

| 设置页里的项 | 系统里要做的事 | 不开会怎样 |
|---|---|---|
| 无障碍服务 →「管理」 | 找到「Tuffy的自动百宝箱」→ 打开（小米要等 10 秒倒计时再确认） | **完全不能用** |
| 手机通知 →「管理」 | 允许 | 看不到结果通知 |
| 精确闹钟 →「管理」 | 允许 | 到点不启动 |
| 悬浮窗 →「管理」 | 允许 | 息屏时无法拉起界面 |
| HyperOS 自启动与后台权限 | 打开自启动 | 被系统清后台后不再定时 |
| HyperOS 锁屏显示与后台弹窗 | 都允许 | 息屏唤醒失败 |

   非小米手机没有后两项，在系统里找「自启动 / 后台运行」类似设置打开即可。设置页的「检查定时通知（90 秒后）」可以用来测试定时是否正常。

3. 再到系统「电池」设置里把它设为**无限制 / 不优化**。
4. 在最近任务里把 Tuffy 的卡片**下拉加锁**，防止被一键清理。

## 4. 设置要做的任务

**ANA 出行挑战**：首页的类别卡片点一下选中、再点一下取消；「调整范围」里填每类最多接多少公里（填 0 = 关闭）。默认：徒步 5、自行车 5、汽车 40、移動手段問わず 40；新干线、飞机默认关闭。

**签到类 App**：首页往下滚，每个 App 一张卡片：

- 右上角开关：是否每天自动执行。
- 「日程与记录」：改执行时间、看历史结果。
- 「立即执行」：马上跑一次（今天漏掉了可以手动补）。

## 5. 每天怎么用

什么都不用做。到点自动执行，跑完发通知：

- **完成**：任务做完，后台已清理、已锁屏。
- **会自动重试**：满足续跑条件时，依次等待 10、20、30、45、60、90、120、120 分钟。连续两次无进展、达到 8 次、下一轮会超过 23:00 JST，或遇到用户停止及账号保护等情形时，停止安排重试。
- **需要人工处理**：通知里写原因，打开 App 首页能看到哪一项没完成；可以点「继续未完成任务」从断点接着跑。

首页「今日结果」显示出行 x/y、广告 x/25、签到状态；「记录」页能看每一次观看和每一次签到的明细。

## 6. 广告、签到与账号操作

- 结果不确定的广告保留待核对。官方明确证明原操作未生效且通过绑定校验时，按对应规则安排有界的新尝试。
- 对特定 Unity 试玩页，只有无法找到关闭键且左上角的「打开商店」单独出现满 30 秒时，才尝试该控件，每条广告最多两次。现有返回路径关闭弹出的商店页，然后继续查找广告关闭键。下载、安装、购买不属于广告恢复步骤。
- TikTok 只点「チェックイン」「獲得する」「アンロック」，不点邀请、提醒、兑换、带 AD 的按钮。
- 不输入任何账号密码；遇到验证码或账号风险提示立即停下，等你处理。
- 不 root，不读其他 App 的数据。

## 7. 常见问题

**装了新版本要重新开无障碍吗？**
使用同签名覆盖安装来保留记录与设置。安装后在「设置」确认无障碍仍已开启并连接，系统若要求重新授权，按提示恢复。

**有一项出行挑战停在 Boost 3/5 或 4/5？**
如果日志显示 `AD_BUDGET_REACHED`，说明 ANA 已达到这项挑战当时的广告预算。实际 Boost 次数保留，下一业务日按官方页面重新检查可执行任务。

**手机被我手动划掉了 ANA，任务还能继续吗？**
在 Tuffy 停止当前运行后，点「继续未完成任务」可以重开 ANA。程序会先核对官方页面和已有记录，再决定安全的续跑范围。

**积分什么时候到账？**
Tuffy 记录官方页面和回执观察。到账时间以对应 App 为准，已显示抽奖结果或奖励提示的项目仍可能等待最终入账。

**日志在哪？**
`/sdcard/Android/data/com.anapocket.auto/files/logs/ana_auto.log`；设置页「运行诊断与导出」→「导出故障包（截图与日志）」可以打一个 zip 包。导出包里有你的账号使用记录，分享前请自己检查。

**能推送到 Telegram 吗？**
可以，可选。设置页「Telegram 通知」填入自己的 Bot Token 和 Chat ID，详见 [TELEGRAM_SETUP.md](TELEGRAM_SETUP.md)。Token 加密保存在手机上。

## 8. 自己编译

需要 JDK 17、Android SDK 34、Gradle 8.9。

```bash
gradle testDebugUnitTest   # 单元测试
gradle assembleDebug       # 调试包（debug 签名）
gradle assembleRelease     # 正式包，需要自己的签名
```

正式包签名通过环境变量或本地 `keystore.properties` 提供：`TUFFY_KEYSTORE_FILE`、`TUFFY_STORE_PASSWORD`、`TUFFY_KEY_ALIAS`、`TUFFY_KEY_PASSWORD`。缺少签名时 release 构建会直接失败。
注意：自己签名的包需要与手机已安装版本的证书一致，才能覆盖安装并保留应用数据。

源码结构、状态机、历史验证记录见 [docs/DEVELOPER_NOTES.md](docs/DEVELOPER_NOTES.md) 和 `CHANGELOG.md`。

## 9. 近期改修（2026-11-08 至 11-14）

### ANA Pocket

- **每日广告回执。** 原生奖励弹窗挡住计数时，有界重试关闭并重读官方次数。只有可绑定的原回执和对应官方增量才结算。结果不明的广告卡保留待核对，有明确官方依据的独立入口可以继续。
- **广告识别与关闭。** 增加对 Moloco `Skip`、Google 多阶段广告及滚动后出现的关闭键、MBridge 原生关闭键、AppLovin 视频跳过与结束卡、Unity WebView 结束卡的识别。ANA 原生广告弹窗和叠加遮罩使用各自的关闭控件。黑屏采样等待画面稳定，超时日志记录探针未能使用的具体条件。
- **中断恢复与出行。** 黑屏或无进展时按原 attempt 和恢复预算，从最近任务重开 ANA，再核对官方续接与结果。ANA 被手动移出最近任务后，「继续未完成任务」可以重新打开 ANA。核对旧 Boost 弹窗前先确认 ANA 在前台。绑定的 Boost 可在官方原生面板核对，包括从商店页返回的情形。孤立的未确认记录单独保留，其他可执行挑战继续。
- **接取和预算。** 识别标题前带截止日期的每日徒步卡。首次接取超时且官方列表证明未参加时，允许符合条件的新接取一次。官方显示 Boost 广告预算用尽时，记录实际次数并从对应弹窗退出。已结束的每日广告待核对项，可以在安全检查通过后与出行恢复隔离。
- **登录与月度徽章。** 登录奖励视频的普通关闭键等待从 35 秒调整到 90 秒，已结束但未确认的登录记录可在重开 ANA 后核对。月度徽章的「動画を見て1点」每天最多尝试一次，支持拆成两行的按钮和进度文字。中断续跑时可在结束前补查，进度只按官方徽章页面确认。

### 签到与通知

- **TikTok Lite。** 新增 07:30 日程，完成 14 天签到、领取昨日奖励和解锁明日奖励。处理遮罩下的底部标签误读、资讯流签到弹窗和有界返回。OCR 按从上到下、同一行从左到右拼接，接受邀请文案中间的常见标点。未识别回执弹窗时回看官方签到卡，以卡片完成状态核对。
- **楽天 PointClub。** 识别官方「達成」和「本日分は抽選済みです」作为相应任务状态，抽奖前等待加载结束，识别「ポイントGETならず」的未中奖页。结果被评分弹窗挡住时使用其关闭键。第一抽已提交、结果待核对时，第二抽仍以官方提供的独立机会为准，第一抽保留待核对。
- **调度与恢复。** 当日受阻后按有限次数续跑。超过三小时的运行先走停止流程，仍未退出时再取消。ANA 未启动时，签到等待到其计划时间后 15 分钟。出行受阻且安全核对通过时，独立的每日广告仍可执行。
- **Telegram。** 改为每日汇总，ANA 与已启用签到完成时发送，最晚等待到 10:00 JST 或最后一个签到计划时间后一小时，截止不晚于 23:00 JST。ANA 随后完成时补发一次。账号保护、签到待核对和无障碍断开等需人工处理的提醒按种类去重，每轮结果仍保留在手机通知中。

### 界面、内存与故障记录

- **首页。** 更新为分组卡片、进度环和底部标签，支持深色模式。类别显示实际完成数，区分进行中、未完成及需核对。当天任务完成后，主按钮进入结果页。
- **运行开销。** 首页大图改用较小的 WebP，页面离开时释放图片。账本读取移到 IO 线程，空闲刷新间隔由 1.5 秒延长至 4 秒。日志内存队列保留 500 行、每行最多 600 字符，证据按运行前缀查找，账号保护窗口扫描串行执行。
- **诊断与收尾。** 故障记录每天最多保留 200 个目录，总预算 256 MiB，优先淘汰较早记录，每份日志尾部最多 192 KiB。符合收尾条件后，从最近任务关闭其他未锁定卡片，保留 Tuffy 和手动锁定的卡片，再锁屏。
